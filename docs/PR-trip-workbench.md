# Карточка выезда: независимый план, сохранение факта и человеко-часы

## Почему

Текущая карточка пересоздаёт связи заявок при сохранении, а карта может восстановить снятые связи. План, посещения и экономический снимок недостаточно разделены. Длительность стоянок автомобиля используется как факт труда без полноценного состава команды.

## Что меняет этот PR

- Постоянные вкладки «План и факт», «Экономика», «История» в существующей карточке.
- Транзакционное сохранение плана с проверкой версии и причиной; сохранение из карты использует тот же RPC.
- Исключённые заявки и предыдущие версии сохраняются; накопленные GPS-точки и присутствие не удаляются.
- Расчёт остатка маршрута от свежей позиции, отдельно от пройденного трека и полного плана.
- Учёт присутствия в человеко-часах по сохранённому составу команды; ручная проверка менеджером без требования ввода часов инженером.
- Явное неполное покрытие; исторический состав не придумывается.
- Предварительный финансовый расчёт плана отделён от существующего снимка начатого выезда.
- Полный и частичный факт различаются; сводка считает маржу по одному набору выездов; ноль отличается от null.
- Проверенное присутствие относится к каждому инженеру и фактическим дням, с корректной обработкой полуночи и летнего времени.
- Тесты SQL на PGlite: rollback, роли, optimistic locking, сохранность факта, детектор и исторические связи.

## Границы

Это первый PR архитектуры, не реализация всех пунктов аудита. Не заменяет автоматический старт/финиш, не меняет retention и не исправляет весь старый RLS. Не реализует атомарное окончательное утверждение/корректировку экономики и одометра, новое планирование нагрузки команд и ручное создание пропущенного посещения. Эти контракты и порядок следующих PR описаны в [проектном решении](trip-workbench-design.md).

## Проверки

- npm test — 235/235, включая 15 SQL-проверок; часовой пояс America/Los_Angeles также проверяется отдельно.
- npm run lint, npm run smoke — проходят.
- SQL выполняется на минимальной схеме, соответствующей нужным частям production, без доступа к production-данным.
- Предпросмотр использует реальную разметку карточки и renderer присутствия с условными данными; это не браузерный E2E с Supabase.
- Браузерная проверка предпросмотра: 1440 px и 390 px, переключение вкладок и отсутствие горизонтального переполнения страницы. На телефоне стоянки показываются блоками.

- Закрыть P0 A01/A02 отдельным PR.
- Прогнать миграцию на staging с полной живой схемой, включая старые триггеры и политики.
- Проверить мобильную карточку и возврат из карты; непрерывность сырых точек после изменения плана.
- Проверить отмену заявки до посещения и после посещения, несколько заявок на одном объекте, поздние GPS-пакеты и изменение команды посреди стоянки.

Пользователь согласовал коммит, PR и слияние. Публикация сайта отделена от слияния: push и pull_request запускают проверки, workflow_dispatch на main дополнительно публикует сайт после подготовки базы. Миграция production этим PR автоматически не применяется.
