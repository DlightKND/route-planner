# DLIGHT · полнота поведения кита 0.6

24 октября 2026. База: опубликованный кит 0.5, `67dbeb7`. [Открыть полный кит](https://dlightknd.github.io/route-planner/preview-design-system.html#full-kit).

Кит 0.5 содержал образцы всех 58 семейств и 8 основ, но рендеринг примера не подтверждал полноту сценария. Проверка 0.6 выявила конкретные пробелы. Они исправлены в прототипе; размеры M 40/48, padding, палитра и радиусы предложения 0.5 сохранены. Production-экраны и запись в Supabase этим изменением не затрагиваются.

| Паттерн | Что было в 0.5 | Что работает в 0.6 | Поведенческая проверка |
| --- | --- | --- | --- |
| Фильтры | Только одиночный выбор | Одиночный статус, независимые признаки, общий сброс. Внутренние мини-пилюли не теряют смысловой цвет | `@kit-filter-controls` |
| Вкладки сущности | Текст панели заменялся целиком | Отдельные связанные tab/tabpanel, черновик каждой панели остаётся при переключении; Arrow/Home/End | `@kit-tab-draft` |
| Навигация | Горизонтальные кнопки, «Ещё» только меняло сообщение | Rail на широком образце / bottom navigation на узком; «Ещё» открывает список и выбранный раздел | `@kit-navigation-more` |
| Профиль | Только preview темы и сообщение о сохранении | Preview аватара и темы, сохранённое состояние отдельно от черновика; ошибка, повтор, удаление аватара и отмена | `@kit-profile-preview` |
| Комментарии | Простой текстовый список | Черновик текста и изображений, сохранность при ошибке, публикация со временем/автором, просмотр вложения, закрепление без потери метаданных | `@kit-comment-evidence` |
| Pending | Блокировалась основная команда; соседняя отмена оставалась активной | Повтор, отмена и редактирование блокируются; исходная подпись сохраняет габариты и доступное имя, виден индикатор | `@kit-pending-controls` |
| Offline | Ошибка reconnect могла очищать признак очереди | Очередь и её данные остаются до успешного подтверждения; повтор возможен после сбоя | `@kit-offline-retry` |

Все операции в ките синтетические: файлы остаются локальными, сервер/разрешения/сессии имитируются. Карта — схема. Это демонстрация компонентов и сценариев, не production-интеграция.

## Связь рекомендации, примера и проверки

Реестр `docs/design-review-examples.json` хранит 58 рекомендаций и, для строк таблицы выше, `behavior_checks`. Проверка `npm run qa:design-patterns` требует:

- точного совпадения рекомендации и R-кодов с таблицей аудита;
- существования визуального образца для каждого ID реестра;
- уникального идентификатора поведения и соответствующего исполняемого теста;
- отсутствия незарегистрированных поведенческих тестов.

В job `design-system-complete` эта проверка запускается до Chromium. Затем выполняются оба набора: геометрия/состояния и поведение. В ките под рекомендацией видны конкретные проверки поведения, если они предусмотрены. У остальных образцов не заявляется тот же уровень проверки только из-за наличия картинки.

Исходный engineer picker остаётся checkbox-popover без поиска. Его название в production-реестре сохранено, а в ките предлагаемый вариант назван отдельно: «Выбор инженеров: поиск и множественный выбор». Это не утверждение, что поиск уже появился на рабочих экранах.

## Воспроизводимая проверка

```sh
npm run lint
npm run qa:design-patterns
npx playwright test tests/visual/design-system-complete.spec.mjs tests/visual/design-system-behavior.spec.mjs --retries=0
```

Новый набор содержит 7 сценариев × 5 ширин × 2 темы. Его нужно оценивать вместе с 110 проверками полного сравнения и 150 проверками прежних сценариев/каталога. Итоги конкретного прогона и скриншоты находятся в Actions artifact `design-system-complete-*`. Полнота этих демонстраций не равна usability-тесту или проверке VoiceOver/TalkBack и реальных серверных прав.
