## 1. Сначала задача и границы решения

Для нового экрана разработчик сначала записывает: **кто → что хочет закончить → что меняется → когда запись становится фактом → что делать при ошибке/отмене**. Затем выбирает один основной переход состояния. Навигация, фильтрация, редактирование черновика и фиксация решения — разные задачи, даже если внешне все выполнены кнопкой.

### Матрица сценариев и приоритетов

| Сценарий / роль | Цель и активная область | Главное действие | Альтернативы / редкие действия | Условие и результат |
| --- | --- | --- | --- | --- |
| Диспетчер, логист / администратор | Запланировать работу из списка | «Создать заявку» или «Создать задание» — по текущей вкладке | Фильтры — chips; открыть запись — ссылка/строка; архив — меню | Создание открывает форму; запись не появляется от выбора фильтра |
| Новая заявка, куратор | Сохранить согласованный состав заявки | «Создать заявку» | «Отмена» secondary; дополнительные параметры раскрываются | Валидация полей; ошибка сохраняет черновик |
| Существующая заявка, куратор | Изменить конкретный раздел | «Сохранить изменения» внутри редактора | «Отмена» secondary; история tertiary | Закрыть с несохранённым — предложить остаться/отбросить; просмотр не выглядит формой сохранения |
| Задание, менеджер | Создать задание / согласовать состав | «Создать задание» / «Сохранить задание» | Создать выезд secondary; история — вкладка; отменить — меню | Текущие права и стадия определяют доступность |
| Результат задания, инженер | Зафиксировать выполненную работу | «Сохранить результат» при вводе; после сохранения — «Передать на проверку» | «Продолжить позже» secondary | Переход меняет главное действие; одновременно два primary не показывать. Учёт результата отделён от присутствия |
| Приёмка результата, куратор | Принять проверенный результат | «Принять результат» | «Вернуть в работу» secondary, перенос остатка — отдельное действие | При блокирующем остатке/несохранённом результате причина видна рядом с кнопкой |
| Выезд, куратор | Запланировать маршрут и команду | «Создать выезд» / «Сохранить изменения» в редакторе | Пересчёт secondary, история tertiary, отмена/удаление в меню | Пересчёт не подтверждает финансовый факт |
| GPS-журнал, логист | Найти запись, требующую решения | «Открыть сверку» для выбранной записи | Фильтры — выбор, открыть карту — secondary; прочее — меню | На повторяющихся строках обычные ссылки/secondary, без ряда жёлтых CTA |
| Присутствие, куратор | Отдельно оценить измерение и принять время | «Сохранить решение» | «Отмена» secondary, пересчёт secondary | Да/Нет меняет черновик. `0` — явное принятое значение; пусто — нет решения. Восстановление начинается с 0 и автоматически не принимается |
| Распределение пробега/времени, куратор | Принять обоснованное распределение | «Подтвердить распределение» | Изменить доли; «Отмена» secondary | Показывать остаток, единицы и основание. Доля времени не означает процент выполнения задания |
| Собственная работа, инженер | Просмотреть назначение, передать факт | Действие, разрешённое текущей стадией | Просмотр карты/истории secondary | Нет права принимать GPS/финансовый факт: текст «Решение принимает куратор», доступный просмотр |
| Настройки профиля, пользователь | Сохранить параметры | «Сохранить настройки», если форма пакетная | Отмена secondary | Switch допустим для отдельно немедленно сохраняемой настройки; не смешивать два режима без пояснения |
| Удаление черновика, разрешённая роль | Удалить конкретную запись | Красная «Удалить черновик» только в подтверждении | «Отмена» secondary и начальный фокус | Назвать номер/объект и последствия; после удаления фокус на соседнюю запись/заголовок |

Проверенные точки текущего кода: `src/workspace-ui.js` (диспетчер, контекст заявки), `src/service-orders.js` (`orderSave`, `orderResultSave`, `orderResultSubmitReview`, `data-review-accept`), `src/trip-workbench.js` (`wbPresenceSave`, `tripAllocationApprove`), `src/entity-actions.js` (редактор и меню), `src/presence-review-controls.js`, `src/presence-review-workspace.js`. Матрица уточняет целевые подписи; старые ID и бизнес-обработчики сохраняются при миграции.

### Одна primary: точное правило

Одна **доступная главная команда на активную рабочую область**. Область — текущая страница/редактор; открытый модальный диалог временно заменяет её, фон inert. Нельзя объявить каждую карточку отдельной областью, чтобы обойти правило. Список использует повторяемые тихие действия. В длинной форме допускается зеркальная sticky-кнопка того же действия, но одновременно доступной/видимой остаётся одна. Каталог вариантов — демонстрация, а не рабочая область.

Primary отвечает «что завершает эту задачу сейчас», а не «что чаще нажимают». При несохранённых изменениях сначала сохраняем; после успешной записи акцент может перейти к следующему действию. Состояние выбора не считается командой и не использует сплошную жёлтую заливку только ради выделения.

## 3. Контракт компонентов

Префикс прототипа `ds-`, опциональная область `.ds-kit`. Источник CSS — `src/ui/design-system.css`; production пока продолжает использовать `.btn` и другие старые классы. Ни один новый экран не должен придумывать собственные HEX/радиусы для этих ролей.

### Button / IconButton / Link

| Вариант | Задача | Вид / контракт | Запрет |
| --- | --- | --- | --- |
| primary | Завершить текущую задачу | `.ds-button[data-variant=primary]`, accent / on-accent | Две разные главные команды рядом; акцент для навигации и каждого фильтра |
| secondary (по умолчанию) | Отмена, возврат, разумная альтернатива | panel, контур input-line, ink | Делать «Отмена» визуально недоступной |
| tertiary | История, детали, небольшая локальная команда | Прозрачная, текст ink, без постоянного контура | Прятать критический выход/сохранение |
| destructive | Запросить опасную операцию | danger-bg + red + подпись «Удалить…» | Сплошная красная primary среди обычных действий |
| danger-confirm | Последний шаг подтверждения удаления | red / danger-ink; заменяет primary в диалоге | Добавлять жёлтую «Подтвердить» рядом |
| icon | Компактная известная команда | `[data-icon]`, зона 44×44, обязательный aria-label; приоритет задаётся variant | «×», «⋯» без имени; tooltip как единственный источник названия |
| link | Перейти к документу/маршруту | `<a href>`; текстовая ссылка подчёркнута, CTA-ссылка может иметь класс button | `<a href="#">` для сохранения или удаления |

Размеры: **S 36 px / 4×12 / 13 px** только тихое действие в плотном desktop; **M 44 / 8×16 / 14**, основной; **L 48 / 12×24 / 14**, мобильный footer. На coarse pointer S становится ≥44. Иконка 16–20 внутри цели ≥44. Это min-height: длинный перевод не обрезается фиксированной высотой.

Подпись 1–3 понятных слова, ориентир до 28 символов, но смысл важнее лимита; не заменять точное действие универсальным «OK». Форма: глагол + объект, одинаковое действие везде называется одинаково. Иконка не обязательна. Все не-submit кнопки имеют `type="button"`.

### Состояния для каждого интерактивного компонента

| Состояние | Визуальная реакция | Поведение / доступность |
| --- | --- | --- |
| default | Роль варианта, без свечения | Семантический HTML, понятное имя |
| hover | Тон текущего foreground 8% поверх поверхности | Только hover + fine pointer; нет информации, доступной только при наведении |
| pressed | Тон 14%, без изменения размеров/позиции | Не путать краткий :active с сохраняемым aria-pressed |
| focus-visible | Outline 2 px `--focus`, offset 3 px | Не обрезать overflow; виден поверх sticky/footer; не менять форму элемента |
| disabled | panel-2 / ink-dim / line, без opacity всего контейнера | Нативный disabled для недоступной команды; причина видна текстом рядом, не только tooltip |
| loading | Индикатор + «Сохранение…», прежняя зона действия | `aria-busy=true`, блок повторной отправки; при aria-disabled обработчик обязательно проверяет busy; статус сообщает начало/итог; исходная подпись восстанавливается |
| error | Текст, контур/иконка red, черновик остаётся | Ошибка у поля `aria-invalid` + `aria-describedby`; ошибка запроса — alert/status; повтор без потери данных |
| read-only | Обычный читаемый текст/значение | Не изображать все данные disabled-полями; показать владельца права действия |

Loading и disabled — разные состояния. Запрос имеет снимок отправленных значений; если разрешено редактирование во время запроса, успех относится к снимку, а новая правка остаётся несохранённой. Нельзя объявлять всю обновлённую форму «сохранённой» по ответу на старую версию.

### Badge / FilterChip / SelectionChip

| Компонент | Значение | Семантика и управление |
| --- | --- | --- |
| Badge | Сообщает статус | `<span class="ds-badge" data-tone="warning">! Нужна сверка</span>`. Без tabindex, cursor:pointer и обработчика. Высота 24 допустима: это не цель касания |
| FilterChip | Меняет набор видимых записей | `<button class="ds-chip" aria-pressed="true">Нужна сверка <span class="ds-count" data-tone="danger">3</span></button>`; ≥44 на touch; имя стабильно, выбор — галочка/рамка + нейтральная поверхность |
| SelectionChip | Показывает выбранную сущность | Текст + отдельная remove button с `aria-label="Убрать Анну Смирнову"`, 44 px цель. Контейнер не button, чтобы не вложить кнопку в кнопку |
| Счётчик | Сообщает количество | `0` только при известном пустом наборе; загрузка «…»; ошибка «неизвестно», не ложный 0 |

Один фильтр группы или несколько — явное правило конкретного списка. Для multi-filter каждая chip независима; «Сбросить фильтры» tertiary появляется при отклонении от default. Выбор «Все» сбрасывает остальные; не показывать одновременно «Все» и частные выбранные фильтры.

### Select / Combobox / Checkbox / Radio / Switch / Tabs

| Пользовательская задача | Компонент | Правило |
| --- | --- | --- |
| Одно значение из короткого известного списка | Нативный `<select>` | Label, пустая option при отсутствии выбора; не подменять выбор предустановленным первым инженером |
| Выбрать инженеров | MultiSelectPopover | Текущий `src/engineer-picker.js` — checkbox-popover/dialog поверх native select[multiple], без поиска; сохраняется выбранный набор ID |
| Найти сущность в длинном списке | Searchable combobox — отдельный будущий вариант | Это не текущий engineer-picker. Ввод текста ≠ выбранный ID; роль combobox допускается после реализации клавиатуры, active option и состояний запроса |
| Выбрать несколько инженеров | Checkbox group + selection chips | Fieldset/legend; Space меняет checkbox; показ количества; недоступные кандидаты с причиной |
| Выбрать одно взаимоисключающее решение | Radio group / segmented visual | Fieldset/legend; нативные radio, стрелки внутри группы; Tab входит/выходит. Никакого автосохранения, если есть «Сохранить решение» |
| Немедленно включить настройку | Switch | `role=switch`, `aria-checked`, стабильная подпись, Space/Enter; pending и ошибка откатывают отображаемый сохранённый статус с сообщением |
| Перейти между панелями одной записи | Tabs | `role=tablist/tab/tabpanel`, aria-controls/selected, roving tabindex; Left/Right, Home/End, Enter/Space при ручной активации. Не выдавать фильтр за вкладку |
| Переход на другой URL | Ссылки навигации | `<nav><a href ... aria-current=page>`, не ARIA tabs |

GPS-решение сохраняет утверждённый бинарный вид Да/Нет, но контракт остаётся **выбором решения в черновике**. Вид тумблера не разрешает автоматически принять восстановление. В каталоге показана нативная radio-семантика; это не команда заменить утверждённую композицию журнала.

Для custom combobox: имя, expanded/controls, активная option через aria-activedescendant, Down/Up для вариантов, Enter выбор, Escape закрывает без потери текущего выбора, Tab завершает взаимодействие. В editable-поле Home/End и клавиши редактирования не отбираются у текстового курсора; переход к крайним вариантам допускается в select-only listbox по его контракту. Ошибки/загрузка не объявляются option. До реализации полного контракта предпочитать native select.

### SegmentedControl: переключатели со сводки

Основа — действующий `.summary-view-switch` в `src/visual-system.css` и `data-summary-view` в `src/app.js`: «Диаграммы / Таблицы». Это отдельный общий компонент, а не две secondary-кнопки и не boolean switch. Контейнер panel-2, padding/gap 2 px, общий радиус 8; цель каждого сегмента ≥44 px, padding 8×12. Выбранный сегмент **ink / panel**, остальные прозрачные / ink-dim. При выборе меняется представление тех же данных, сохраняются период, команда и фильтры. Жёлтая primary остаётся для команды.

| Назначение | Вариант | Состояние и поведение |
| --- | --- | --- |
| Диаграммы / таблицы, список / доска | ViewSegment, контрастный нейтральный | `role=group` с именем; нативные button + aria-pressed, ровно один true; Tab/Space/Enter, дополнительно Left/Right/Home/End; фокус остаётся на сегменте |
| Неделя / 2 недели / месяц | PeriodPreset, мягкий | Общее семейство геометрии; выбранный panel-2 / ink с input-line, не новая команда. В произвольном диапазоне все пресеты false |
| Одно значение поля формы | SegmentedRadio | Нативные radio под общим видом; fieldset/legend; сохранение вместе с формой. Не объявлять немедленно применённой настройкой |
| Разделы карточки с разным содержимым | Tabs | Контракт tablist/tab/tabpanel из раздела выше, не group toggle-кнопок |
| Включить/выключить параметр | Switch | Отдельный бинарный компонент; не использовать для «Диаграммы / Таблицы» |

Hover — panel / ink у невыбранного, pressed — контур focus без сдвига; focus-visible общий; disabled с видимой причиной. При асинхронной смене представления сохранять выбранный сегмент, показывать pending/error в области данных, не подменять ошибку пустым набором. Выбранность обозначена заливкой, контуром, весом и aria-pressed; в forced-colors сохраняется outline. Для длинных переводов контейнер переносит сегменты целиком, не сжимает цель ниже 44 px.

### CountBadge: вложенная мини-пилюля из журнала

Предпочтительный паттерн **«Название [число]»**, не «Название · число». Источник — `.unassigned-filter > button b` и `data-ut-mode=pending` в `src/unified-journal.css`. В каталоге это `.ds-count` внутри FilterChip/SegmentedControl/кнопки вкладки. Счётчик — span без отдельного фокуса и обработчика; нажатие на него активирует родительский элемент. Доступное имя родителя включает название и число; при сокращении `999+` полное значение передаётся через aria-label родителя.

| Смысл | Токены / пример | Правило |
| --- | --- | --- |
| Общее количество, размер команды | --count-neutral-bg / ink | Нейтральный; не превращать любую ненулевую цифру в предупреждение |
| Требуется решение, как «Нужна сверка» в журнале | danger-bg / red | Привлекает внимание к действию; подпись объясняет смысл, красный не означает автоматически техническую ошибку |
| Неопределённость, восстановление, ожидание | warning-bg / warning | Использовать, если именно это означает показатель |
| Подтверждено / принято | success-bg / green | Только для подтверждённого факта |
| Известный ноль | --count-neutral-bg / ink | `0`, без тревожной заливки, даже внутри фильтра проблем |
| Загрузка / ошибка загрузки | `…` / `—`, нейтральный | Имя «Количество загружается» / «Количество неизвестно»; никогда ложный 0 |

Нейтральный фон `--count-neutral-bg = color-mix(in srgb, var(--ink) 10%, transparent)` повторяет журнал: мини-пилюля видна и на выбранной panel-2, и на обычной panel.

Размер: min-width 24, min-height 22, padding 1×6, radius pill, 12/20 px 600, tabular-nums; это не самостоятельная цель касания. Отступ от подписи — 8 px. Семантические bg/fg **не наследуют цвет выбранного родителя**, сохраняются при hover/pressed/selection и смене темы. Нельзя делать у выбранного фильтра любой счётчик жёлтым/белым и терять его смысл. Для нулей/неизвестного не использовать только цвет как различие.

```html
<button type="button" class="ds-chip" aria-pressed="true">
  Нужна сверка <span class="ds-count" data-tone="danger">3</span>
</button>
<div class="ds-segmented" role="group" aria-label="Представление статистики">
  <button type="button" aria-pressed="true">Диаграммы</button>
  <button type="button" aria-pressed="false">Таблицы</button>

```

### Семейство DateControl: не один универсальный календарь

Основа — `renderPeriodSelector` / `renderJournalPeriod` / `rangeBar` в `src/app.js`, арифметика `src/core/summary-period.js` и границы `src/core/calendar-period.js`. Каталог вызывает **те же production-функции**, а не копирует расчёт недель/месяцев. Нативные picker-панели зависят от браузера/ОС; оформление полей и общая обвязка едины. Собственный сеточный календарь требует отдельной доказанной потребности и полного keyboard-контракта.

| Компонент / сценарий | Вид и значение | Применение |
| --- | --- | --- |
| DateField — дата выполнения, SLA | `input[type=date]`, label + helper/error; ≥44, на touch текст16 | Один календарный день; необязательная дата может быть пустой. Placeholder не заменяет label |
| DateRange — период заявки/задания/аналитики | Два поля «Начало» / «Конец» в общей группе | Проверка обеих границ; не менять местами молча. Ошибка у конца, фокус на ошибочном поле |
| PeriodNavigator — сводка и график | Сегодня + Week/Fortnight/Month; ряд ← / иконка календаря + диапазон / → | Стрелки с aria-label; центральная кнопка открывает draft DateRange в dialog; не выглядит полем без подписи |
| MonthNavigator — журнал | ← / «октябрь 2026» с выбором периода / → | Шаг ровно календарный месяц. Общая геометрия с PeriodNavigator; компактная центральная подпись сохраняет год |
| MonthField — отчётный месяц | `input[type=month]`, значение YYYY-MM | Месяц, не условные 30 дней; при fallback браузера явно проверять формат |
| TimeField — время внутри известной даты | `input[type=time]`, точность по задаче | Подпись содержит дату/зону рядом; «10:20» само по себе не определяет момент |
| DateTimeField — срок с точным временем | `input[type=datetime-local]` + явная зона | datetime-local не хранит часовой пояс; преобразование выполняет доменная логика. DST неоднозначность/несуществующее время валидируются, не исправляются молча |

**Режимы периода:** сводка использует календарную неделю с понедельника, две недели, календарный месяц. Личный график в текущем приложении использует окно от сегодня на 7/14/30 дней. Эти разные правила задаются режимом компонента, не выводятся из похожей подписи «Месяц». В журнале основной шаг — календарный месяц; произвольный диапазон не подписывается как один месяц, если пересекает несколько. Сегодня возвращает текущую календарную единицу; у произвольного окна сохраняет включённую длину.

Выбор пресета и стрелки применяются сразу и обновляют данные; период, введённый в диалоге, — черновик до «Применить период». Cancel/Escape оставляет исходный диапазон, возвращает фокус; повторное открытие заполняется применёнными датами. При custom диапазоне показывать «Произвольный период» и снять все активные пресеты. Диалог имеет одну primary; пустое обязательное поле, несуществующая дата и начало позже конца не применяются. Кнопки навигации не блокируются только из-за отсутствия записей в текущем периоде.

Диапазон **включает оба календарных дня**. Запросы используют начало первого дня и исключительную границу следующего дня после конца, в Europe/Kyiv через `calendarPeriodBounds`; нельзя считать локальные дни простым прибавлением 24 часов к UTC-моменту при переходе DST. Перенос календарного месяца сохраняет календарный смысл (31 января → февраль целиком), а не прибавляет 30 дней. Показывать год при переходе через декабрь; одна дата не сдвигается из-за зоны устройства.

Адаптивность: ряд стрелки–диапазон–стрелки остаётся единым; центральная подпись переносится при необходимости, без скрытых крайних дат. Цели стрелок ≥44, календарная иконка18, radius контейнера12/контрола8. На телефоне пресеты могут перейти на отдельную строку; поля диалога идут друг под другом, не переполняют экран. Disabled означает реальное доменное ограничение с причиной; readonly — текстовое значение; pending/error относится к загрузке данных, даты и черновик сохраняются.

### Field / Textarea / Number / Date

Label всегда видим, placeholder — только пример. Helper до ошибки объясняет формат; ошибка заменяет/дополняет helper и связана с полем. Required обозначается словом/пояснением, а не только красной звёздочкой. Проверка на blur/submit, без красного состояния до первого взаимодействия. После неуспешной отправки фокус на первое ошибочное поле; длинная форма дополнительно имеет сводку ошибок со ссылками.

Число хранится как значение с единицей; `null`, пустая строка и `0` имеют разный смысл. Отрицательные минуты и дроби там, где нужны целые, не принимаются. Для дат пользователь видит локальную дату/зону; формат хранения не попадает в подпись. Не стилизовать некликабельное значение как выпадающий список.

### Menu / Dialog / Feedback

Редкие команды прячутся за именованной кнопкой «Другие действия». Если это disclosure с обычными ссылками — `aria-expanded`/`aria-controls`, обычный Tab. Если используется `role=menu`, нужны arrow-навигация, Home/End, Escape и возврат фокуса; нельзя добавлять роль без поведения. Текущий `mountEntityActions` открывает **диалог выбора**, поэтому `aria-haspopup=dialog` сохраняется до полноценной замены.

Диалог: нативный `<dialog>.showModal()`, имя от заголовка, фон inert, Escape отменяет безопасное редактирование, возврат фокуса инициатору. Для несохранённых правок использовать существующий `protectNativeForm` (`src/modal-shell.js`), не глобальный `window.confirm`. В опасном подтверждении начальный фокус — «Отмена», точный объект/последствие в тексте, красная финальная команда. На телефоне сложный редактор может быть fullscreen; контент не скрыт клавиатурой и footer учитывает safe-area.

Компактные панели графика («Фильтры», «Рабочий обзор») используют общую шапку: padding 16 px, заголовок слева 18/25 px semibold, единый SVG-крестик 20×20 px справа. Цель закрытия 44×44 px на ПК и 48×48 px на телефоне; высота верхней зоны с ручкой мобильной панели совпадает. В фильтре телефона «Применить» находится в нижнем footer с safe-area, сброс — в содержимом. Подтверждение несохранённых правок сохраняется. Рабочий обзор остаётся немодальной контекстной панелью на ПК.

Рельсы диспетчера и каталога используют общие `workspace-section-rail` / `workspace-page-tabs`: отступы 24×32 px на ПК, 16×16 px на телефоне, 16 px между заголовком и вкладками, вкладки высотой 48 px. Активная линия 2 px лежит на нижнем разделителе, без отдельного пустого ряда. Подзаголовок относится к общей вспомогательной типографике. На узком экране прокручивается ряд вкладок, а не вся страница.

Feedback: pending «Загружаем…»; empty «Пока нет выездов» + следующий шаг; error «Не удалось загрузить» + повтор; stale «Данные на …, обновление не удалось»; read-only «Решение принимает куратор». Toast только для короткого некритического успеха; ошибка сохранения остаётся рядом с формой, пока не исправлена. Loading не показывает выдуманный процент. На карте уже есть FAB «Создать точку» (`pointToolsFab`); для неё действуют правила [навигации и FAB](#pattern-navigation). В других разделах отдельная FAB требует подтверждённой задачи, а не добавляется рядом с готовым главным footer-действием.

## 4. Примеры интеграции

```html
<form data-action-scope="presence-review">
  <label for="acceptedMinutes">Принятое время, мин</label>
  <input id="acceptedMinutes" type="number" min="0" step="1"
         aria-describedby="minutesHelp minutesError">
  <p id="minutesHelp">0 — подтверждённый ноль; пусто — решение не задано.</p>
  <p id="minutesError"></p>
  <button type="button" class="ds-button">Отмена</button>
  <button type="submit" class="ds-button" data-variant="primary">
    Сохранить решение
  </button>
  <p role="status" aria-live="polite"></p>
</form>
```

```js
// Контракт асинхронной команды; server-side permissions остаются обязательными.
let busy = false;
async function saveDecision(button, status, snapshot) {
  if (busy) return; // aria-disabled сам по себе не блокирует click/Enter
  busy = true;
  button.setAttribute('aria-busy', 'true');
  button.setAttribute('aria-disabled', 'true');
  status.textContent = 'Сохраняем решение…';
  try {
    await persistDecision(snapshot); // существующий обработчик приложения
    status.textContent = 'Решение сохранено';
  } catch (error) {
    status.textContent = 'Не удалось сохранить. Проверьте связь и повторите.';
    // Не очищать поля и не закрывать редактор.
  } finally {
    busy = false;
    button.removeAttribute('aria-busy');
    button.removeAttribute('aria-disabled');
  }
}
```

Для production сначала подключить кандидата в выбранной области через `.ds-kit` либо адаптер, затем переносить классы без изменения бизнес-обработчика. Не добавлять `.ds-kit` на весь body приложения: её layout предназначен для каталога. При первом внедрении отделить page-layout каталога от компонентных правил.

## 5. Доступность и платформенные правила

Это web/PWA: нативные HTML-контролы, browser back, реальные ссылки, работа keyboard и touch. Не копируем iOS/Android навигацию внутрь веб-формы. На телефоне цель касания **≥44×44**, ключевой footer **48 px**, gap **8 px**; плотный S разрешён только fine pointer. Проектная норма 44 выше базового WCAG 2.2 AA 2.5.8: там 24×24 CSS px с оговорёнными исключениями, а 44 относится к enhanced-критерию. Это не заявление о полной сертификации приложения.

Текст ≥4.5:1, крупный ≥3:1; значимые контуры/индикаторы ≥3:1 к прилегающей поверхности. Проверять реальные пары обеих тем, а не произвольные токены по отдельности. Выбранность имеет нецветовой признак. Фокус видим и не перекрывается fixed footer. Порядок DOM совпадает с чтением, zoom 200% и ширина 320 CSS px не теряют действия; горизонтальная прокрутка только для действительно двумерных данных. Reduced motion и forced colors не убирают выбранность/фокус.

Источники поведения и критериев (прочитаны 24.10.2026): [WAI Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/), [APG patterns](https://www.w3.org/WAI/ARIA/apg/patterns/), [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [WCAG non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Это источники конвенций; палитра и композиция следуют приложению и существующим референсам.

| Сейчас | Целевой компонент | Порядок |

| `.btn.amber` | Button primary | Сначала убрать конкуренцию действий; затем визуальный адаптер |

1. **P0:** принять матрицу задач, названия, границы primary; выбрать один экран (редактор результата задания) для пилота. Не менять все формы одним CSS-патчем.
2. **P1:** вынести общие tokens и Button/Field/Badge без изменения эффективных значений; добавить совместимые адаптеры старых классов, подключить пилот.
3. **P2:** фильтры, radio/segmented, switch и picker; проверить keyboard и различие draft/immediate.
4. **P3:** перенос остальных экранов, удаление дублирующих CSS и адаптеров после проверки сценариев.

Владение: одна каноническая спецификация `docs/design-system.md`, компонентный источник `src/ui/`, локальные правила GPS в [journal-design-system.md](journal-design-system.md) дополняют её. Новый тип допускается, если описан сценарий, существующие варианты не подходят, определены все состояния, mobile/keyboard и обратная совместимость; решение проходит обычный code/design review. Вариант не создаётся ради другого цвета одного экрана. Версия меняется при изменении контракта, визуальные исключения получают причину и план снятия.

## 7. Критерии проверки

Автоматически: вложенные счётчики и их контраст при selection, переключение представления с клавиатуры, отмена и ошибки периода, календарные месяцы/граница года/високосный февраль/произвольное окно; сборка автономного каталога из production tokens; Chromium 360/390/768/1024/1440 × light/dark; отсутствие горизонтального overflow, одна primary в активной форме, keyboard/фильтры, validation 0 vs empty, loading и блок повторной отправки, retry с сохранением данных, диалог Escape/focus return, контраст основных пар и размеры touch. Файл `tests/visual/design-system-catalogue.spec.mjs`; скриншоты сохраняются как свидетельства, а не как доказательство пользовательского понимания.

Далее провести 5–7 коротких сессий с логистами/инженерами: найти нужную сверку; отличить GPS от принятого времени; подтвердить 0; отменить черновик; передать результат; восстановиться после ошибки. Проверять завершение без подсказки, неверные подтверждения, время поиска главной команды и понимание последствий. Любая случайная необратимая операция блокирует выпуск; повторяющаяся путаница у двух участников требует пересмотра компонента/подписи. Это план, реальные пользовательские тесты в рамках 0.3 не проведены. A/B имеет смысл после пилота и достаточного трафика, с метрикой завершённой задачи и guardrail ошибок; он не заменяет проверку понятности.

## 8. Покрытие и границы готовности 0.3

В живом каталоге реализованы Button/Icon, FilterChip+CountBadge, Badge, Select, Checkbox/Radio/Switch, SegmentedControl сводки, PeriodNavigator и DateRange dialog, Date/Month/Time/DateTime поля, feedback и destructive dialog. Для остальных найденных семейств контракт и исходники перечислены в [аудите покрытия](design-pattern-audit.md) и [реестре](design-patterns.json). Текущий engineer-picker не имеет поиска. Removable SelectionChip и кастомная сетка календаря — возможные будущие варианты, а не подтверждённые отдельные production-компоненты. Это явный следующий этап, не основание создавать локальные варианты на новых экранах.

Перед пилотом проверять инвентарь по **каждой задаче**, включая представление, период, команду, поиск, сортировку и редкие команды. Если контрол есть на рабочем экране, он должен иметь строку в матрице и семейство компонентов — раздел не считается охваченным по одному образцу кнопки.


## 9. Дополнения по полному инвентарю приложения

Реестр: [design-pattern-audit.md](design-pattern-audit.md). Версия 0.3 расширяет **спецификацию**; каталог остаётся 0.2, рабочие экраны сохраняют текущую реализацию. Правила ниже — целевой контракт и критерии приёмки пилота, а не утверждение, что все текущие обработчики ему соответствуют.

<a id="pattern-selection"></a>
### Поиск и выбор сущности

**SearchField:** видимая подпись или доступное имя, search icon декоративна; отдельная очистка с именем «Очистить поиск», зона44. Пустой запрос возвращает исходный набор. Escape в поле сначала закрывает предложения/очищает только явно согласованное состояние, а не закрывает родительский редактор. Фокус не теряется после перерисовки. Результат фильтрации не записывает сущность на сервер.

Для удалённого поиска — debounce по задаче (в уведомлениях сейчас250ms), индикатор и отмена/игнорирование устаревшего ответа по request/query version. «Ничего не найдено», «Введите запрос», «Загружаем» и «Ошибка поиска» — разные состояния; старая выдача при ошибке подписана как старая. Результат сообщается polite-status, не каждым нажатием клавиши. Условие поиска, период и команда сохраняются при смене представления.

**SearchResultPicker:** адресные результаты — список именованных кнопок/ссылок с вторичной строкой адреса. Напечатанный адрес ≠ выбранная координата; показать выбранный объект и возможность заменить/снять. Если превращаем поле в combobox — нужен его полный APG-контракт, а не только стрелка и role.

**MultiSelectPopover:** текущий выбор инженеров — группа checkbox в немодальном popover/dialog. «Готово» закрывает выбор; это не означает запись всей формы. Набор ID принадлежит native select; disabled-кандидаты имеют причину, выбранный кандидат не исчезает молча. Trigger показывает первого человека и `+N`, полное имя/количество доступны. При закрытии Escape/«Готово» — возврат фокуса; при внешнем клике фокус переходит к выбранной внешней цели, а не прыгает назад. Открытый picker внутри modal размещается в его разрешённом top layer. Поиск внутри него пока не реализован и не должен объявляться готовым.

**Комбинации фильтров:** явно определить AND/OR, общий сброс, число применённых условий и реакцию на пустую выборку. Сброс фильтра не очищает несохранённый документ. Применяемые сразу фильтры отличаются от draft-фильтров с кнопкой «Применить»; не смешивать режимы в одной панели без указания.

<a id="pattern-inputs"></a>
### Числовое поле, slider и color picker

Число: label + единица, допустимый диапазон и точность. Деньги — валюта и согласованное округление; количество — штуки/нормочасы/минуты; процент — явное «доля времени» или «выполнение», без взаимозамены. Decimal input учитывает способ ввода пользователя, хранение остаётся числом; недопустимый ввод объясняется у поля, не исправляется молча. Не применять числовые спиннеры к телефону, ID, артикулу. Для точного значения slider всегда имеет видимое число и альтернативный ввод/кнопки изменения.

**RangeSlider:** native range предпочтителен. В приложении есть `rBuf` (0–50км, шаг1), `rIso` (0–60мин, шаг5) и отдельный вертикальный slider разрыва графика. Track4px, thumb20–24px внутри доступной зоны≥44, подпись/значение/единица рядом; заполнение и незаполненная часть различимы в обеих темах. Точное значение не показывается только в hover-tooltip. Для custom — имя, min/max/now, valuetext с единицей и orientation; стрелки меняют шаг, Home/End — границы. В вертикальном графике направление увеличения согласовано со временем вниз и объяснено. Escape/pointercancel возвращают значение до жеста; drag-preview не означает серверное сохранение. Disabled с причиной, readonly — число. Проверить keyboard и touch assistive tech на реальном устройстве перед миграцией.

**ColorPicker:** цвет относится к объекту карты, не к теме UI. Native input color + название/доступный hex или эквивалентная текстовая идентификация; swatch сам по себе не обозначает состояние/тип клиента. Цель≥44, swatch24, общий радиус8 и контур input-line. Не применять выбранный пользователем цвет к подписи без контрастного слоя; стандартные semantic-токены приложения этим picker не меняются. Preview локальный до согласованного сохранения формы.

<a id="pattern-media"></a>
### Фото, файлы и просмотр доказательств

**Upload:** именованная кнопка открывает native file dialog; допустимые типы, количество и ограничения объясняются до выбора. Нельзя требовать drag-and-drop как единственный способ. Состояния каждого файла: выбран/подготовка/отправка/на сервере/в локальной очереди/ошибка; реальный прогресс либо «Отправка файла N из M», без выдуманного процента. Ошибка одного файла не объявляет весь набор отправленным. Сохранять успешные файлы, повторять конкретную ошибку без дубликатов. Выбор файла и его серверная запись — разные события.

Карточка фото содержит thumbnail с устойчивым aspect-ratio, тип доказательства, статус и именованные «Открыть»/«Удалить». Если исходный размер/лимиты неизвестны, не придумывать их в общей системе: доменные параметры находятся рядом с upload-конфигурацией. Фото в offline-очереди не обозначается как загруженное. Удаление ещё не отправленного файла предупреждает о потере локальной копии; удаление серверного фото — отдельная операция с понятными последствиями.

**ImageViewer:** modal/fullscreen с именем фотографии, явным закрытием≥44, Escape, focus return и scroll-lock фона. Масштабирование не блокирует browser zoom; если есть prev/next/zoom — именованные кнопки, пределы и keyboard. Не добавлять неработающие affordances. Loading, ошибка URL и недоступность фото имеют текстовый fallback и повтор. Истечение signed URL — не «фото отсутствует». Иконка фото/автор/дата доступны без необходимости читать сам bitmap.

<a id="pattern-navigation"></a>
### Навигация, FAB и пространственная компоновка

Rail на desktop и нижняя навигация на телефоне показывают текущий раздел не только цветом: подпись/состояние; активный пункт имеет aria-current для ссылочной модели. Для переходов — реальный URL, browser back и возврат к исходному списку/scroll/фильтрам; команды «выйти» и «создать» не маскируются под раздел. Кнопка «Ещё» открывает именованный слой с текущими доступными разделами. Вложенный экран имеет понятный возврат к своей сущности, не безусловный прыжок на сводку. Роль пользователя определяет доступные пункты; отсутствие права не заменяется пустым экраном.

**Существующая map FAB:** «Создать точку», круглая/пилюльная цель≥48, icon20–24, доступное имя и пояснение текущего режима. Размещается над шторкой/нижней навигацией/safe-area и не закрывает zoom, attribution или выбранный маркер. При режиме построения маршрута нужно проверить и согласовать конкуренцию с его CTA: одна primary текущей задачи; создавать точку не должно быть случайным действием вместо расчёта. FAB не добавляется автоматически в остальные разделы.

**Responsive/sticky:** до760px секции могут перестраиваться в один столбец; граница выбирается по содержимому, не по модели устройства. Header/footer не дублируют активную primary в одной видимой области. Учитываются virtual keyboard, safe-area, bottom rail и sheet height; последняя строка и ошибка поля достижимы. Модалка, picker, подсказка и sticky-footer имеют проверенный порядок слоёв; нельзя исправлять всё произвольным z-index. Поддержать reflow/zoom, reduced-motion и forced-colors; важный контент не скрывать только ради экономии места.

<a id="pattern-layers"></a>
### Disclosure, подсказка, popover и sheet

**Disclosure/Accordion:** native details/summary либо button с expanded/controls; Enter/Space. Заголовок и метаданные остаются читаемыми при сворачивании. Поле с ошибкой раскрывается перед переводом фокуса. Несколько секций могут быть открыты, если реальная задача не требует exclusivity. Группы моделей техники остаются группированным списком; role=tree требует отдельной arrow-клавиатуры и не добавляется из-за визуальной вложенности.

**HelpPopover:** текущий `info-hints` — пояснение по нажатию, не только tooltip при hover. Имя кнопки объясняет предмет; expanded/controls, Escape, внешний клик, позиция в viewport. Нажатие на «?» внутри label не переключает checkbox. Если внутри есть ссылки/команды, это интерактивный popover с управлением фокусом, а не role=tooltip. Критическая инструкция и причина disabled видимы рядом с полем, не спрятаны в «?».

**ContextPopover:** текущий `openContextPanel` немодальный, фон доступен, aria-modal не ставится. Позиционирование привязано к trigger, min-width по содержимому, viewport margin8; resize/scroll не оставляют панель у старой координаты. Close/Escape возвращает фокус инициатору, внешний клик — к внешней цели. Подложка модального окна к нему не применяется. Нельзя применять одну и ту же dismissal-политику к информационной подсказке и редактору с черновиком.

**BottomSheet:** у карты есть snap-положения. Видимая ручка/кнопка имеет имя, управление нажатием и доступный способ выбрать положение без точного drag; внутренний scroll отделён от drag ручки. Отмена жеста не фиксирует случайное положение/данные. В раскрытом состоянии согласован доступ к карте; модальность объявляется только при реальном inert-фоне и focus trap. Деструктивное действие не размещается на ручке. Fullscreen-редактор имеет явное «Закрыть/Назад», даже если sheet можно смахнуть.

<a id="pattern-data"></a>
### Карточки, таблицы, карта и лента

**RecordCard/List/Board:** одна основная точка открытия, короткое имя/номер, стадия, дата/команда и отдельные команды. Не вкладывать button в button или ссылку; если строка содержит checkbox и меню, контейнер не забирает их нажатие. Выбранность, текущая открытая запись, hover и стадия — разные состояния. В board число относится к видимому набору столбца; нет данных и ошибка столбца различаются. Переключение список/доска сохраняет scope и выбранную сущность.

**LoadMore:** добавить порцию, сохранив прежние записи и фокус; явный pending, защита от повтора и отдельная ошибка порции с retry. Первый load-error не превращается в пустой список; ошибка второй страницы не стирает первую. «Все выбраны» означает известный scope, не невидимые серверные записи. Если есть общий checkbox, частичный выбор отображается через indeterminate/mixed, а не checked для всего набора. Infinite scroll не вводить без доступной альтернативы. Пагинация с номерами — другой паттерн, в найденных очередях её нет.

**DataTable/Chart:** caption/заголовок, единицы и одинаковое определение показателей. Числа выровнены, tabular-nums, null/неизвестно ≠0; явно подписан период. Таблица остаётся доступной альтернативой диаграмме, не теряет данные при переключении. Общая шкала там, где сравниваются величины; план/факт и благоприятное/неблагоприятное отклонение не обозначаются только цветом. Действия строки/редактирование отдельны от выбора. Если позже появится интерактивная сортировка — имя столбца и aria-sort; сейчас внутренний sort() не считается готовым сортируемым header. Двумерные данные могут иметь локальный scroll, не горизонтальный scroll всей страницы.

**MapExplorer:** интерактивная карта — именованный region с управлением keyboard, миникарта-превью — img/описание и отдельная кнопка открытия, не ловушка scroll/touch. Zoom/слои/центрирование имеют имена и цели касания; выбранный маркер связан со строкой списка. Сгруппированные остановки раскрываются списком, совпадающие координаты не скрывают записи. Карта не единственный способ выбрать объект: список/хронология дают эквивалентный путь. Не терять attribution. Tile/геокодинг error отличается от отсутствия координат и разрыва GPS.

**EvidenceTimeline:** измерено GPS, достроено, предложено и принято куратором показываются отдельно. Восстановление не становится фактом от нажатия пересчёта; принятое0 отличается от отсутствия решения. Карта, список остановок и временная шкала показывают одну выбранную сущность. Факт телеметрии имеет «на …», не выдаётся за live без свежих данных. Измеренный градиент скорости и оранжевый пунктир — цвета данных, не новые семантические роли UI.

**Activity/Comment:** дата/автор/тип события, историческое изменение и текущее состояние различны. Комментарий — textarea с черновиком и явной отправкой; Enter вводит строку, submit-клавиша только если объявлена и есть обычная кнопка. Pending блокирует дубль; ошибка сохраняет текст. Закрепление — состояние действия с понятным именем, не обещание нового сообщения; раскрытие закреплённого не дублирует/теряет событие в общей ленте. Встроенные фото открываются доступной кнопкой. Лента с limit не называется полной историей без соответствующей загрузки/пояснения.

<a id="pattern-workflows"></a>
### Повторяемые строки, массовые операции и манипуляции графика

**EditableItems:** стабильный ID строки, label каждого поля в контексте работы/материала, единицы, зависимые итоги. Добавление переводит фокус в новую строку, удаление — в логичный соседний контрол. Удаление строки черновика не требует модального подтверждения каждый раз, если оно обратимо до сохранения; удаление серверного факта — отдельный контракт. Не терять строки при перерисовке picker. Ошибка у конкретной строки и общая сумма/остаток видны вместе; итог не обновляется как подтверждённый до успешной записи.

**BulkSelection/Preview:** checkbox выбирает запись, не открывает её. Toolbar показывает количество/область выбора, «Снять выбор» и доступные операции. Перед объединением треков/созданием цепочки документов — preview с порядком, объектами и последствиями; после изменения состава/порядка старый preview считается устаревшим. Pending не допускает двойной commit; частичная ошибка показывает, что создано/не создано. Не подтверждать одновременно восстановление GPS или финансовый факт только из-за объединения источников.

**Reorder:** grip означает перенос, но есть кнопки «Выше/Ниже» или редактор порядка. Preview, допустимая цель и результат понятны; Escape/pointercancel возвращает порядок. После перемещения фокус остаётся у элемента и объявляется новая позиция. Маршрут после перестановки требует пересчёта/статуса «не рассчитан», не сохраняет старые км как новые. Карточка board может менять стадию только по доменным правилам, а не потому, что курсор попал в колонку.

**ScheduleManipulation:** отличать click/open, scroll, перенос, изменение границы, разделение и объединение. Snap и минимальная длительность заданы доменом. Во время жеста — preview, нет серверной записи на каждом pointermove; подтверждение/запись после завершения согласно сценарию. Escape, потеря pointer capture и отмена должны восстанавливать исходную геометрию. Для роли без права редактирования сохраняется открытие и просмотр. Перенос/разделение доступны через контекстный редактор или клавиатуру: жест не единственный путь. Короткий блок не превращается в цель меньше44 без эквивалентного доступного выбора.

**AllocationEditor:** список участников/работ, единицы, принятый итог и нераспределённый остаток. Входящий GPS-факт, редактируемое восстановление, доля времени и процент выполнения различаются. Удаление строки/участника сначала меняет draft, пересчёт показывает последствия до сохранения. Итог проверяется по допустимой точности; нельзя скрыть разницу округлением или автоматически разложить остаток и представить его принятым куратором. При readonly данные видны, причина отсутствия действия указана.

<a id="pattern-feedback"></a>
### Ожидание, уведомления и внешние действия

**Loading/Progress/Skeleton:** scope ожидания совпадает с обновляемым блоком; существующие значения не заменяются0. `busy` с известной долей может показывать прогресс; при неизвестной — stage-text/indeterminate. Skeleton соответствует геометрии ожидаемого содержимого, aria-busy на области и один status; анимация не обязательна и отключается reduced-motion. Timeout не равен пустой выдаче. Отмена показывается только если реально отменяет запрос/операцию; после успеха/ошибки controls возвращаются в корректное состояние и статус не исчезает до прочтения критической ошибки.

**NotificationInbox:** событие, непрочитанность и «требует решения» — разные признаки. «Прочитать все» имеет определённый cutoff/scope, не принимает задачи и не включает push. Новые события во время операции не помечаются прочитанными молча. Счётчик показывает достоверное число/99+ с полным accessible name; неизвестность не очищает фактические непрочитанные как0. Открытие уведомления ведёт к нужной записи/разделу с обычным browser back. Запись удалена/недоступна — понятный fallback, а не пустая карточка. Push на устройстве не заменяет inbox.

**Toast/Banner/Error:** краткий успех — toast, долговременная проблема/запрет/очередь — постоянный banner/inline. Цвет дополняет текст; роль alert только для срочной ошибки, status — для обычного обновления. Несколько параллельных запросов не стирают важную ошибку мгновенным «Сохранено» другого блока. Retry относится к конкретной ошибке. Если нужен action в toast, он доступен keyboard и не исчезает раньше взаимодействия.

**Copy/ExternalLink:** «Скопировано» только после успешного clipboard promise; при отказе — доступный текст для ручного копирования. Внешняя карта/приложение названы в действии; необязательный новый tab не заставляет терять текущий черновик. Координаты и маршруты не выглядят внутренней кнопкой сохранения. Ошибка внешнего сервиса не меняет данные выезда на пустые.

<a id="pattern-recovery"></a>
### Черновик, конфликт, offline и корзина

**DraftGuard:** различать просмотр, изменённый draft, pending, сохранённое на сервере и локально отложенное. При уходе/связанной операции — конкретные «Сохранить и продолжить», «Не сохранять», «Остаться» по необходимости. Не показывать три одинаково главных кнопки. Cancel/Escape возвращает в исходное редактирование. Успешный ответ относится к отправленному snapshot; новая правка после отправки остаётся dirty. Сохранять baseline только после подтверждённого успеха. Черновик привязан к пользователю и сущности, не переносится другому аккаунту.

**RevisionConflict:** отдельное состояние от сети/валидации. Сказать, что запись изменилась; сохранить локальный draft, предложить загрузить актуальную версию/сравнить/повторить после согласования. Не заменять серверный факт устаревшим snapshot и не запускать бесконечный retry конфликта. До выбора пользователя readonly-факт и локальная правка визуально различимы. Проверять этот сценарий в editor результата задания, где уже есть expected revision.

**OfflineQueue:** «Сохранено на устройстве, ждёт отправки» ≠ «Сохранено на сервере» ≠ «Принято куратором». Banner содержит свежесть snapshot, размер очереди и заблокированную запись/причину. Повтор отправки доступен отдельно, не требует заново заполнять форму. Очередь изолируется по пользователю; logout/смена аккаунта не показывают чужие данные. Pending, blocked, retry, synced и конфликт не сливаются в одну красную метку. Восстановление соединения не объявляется по одному navigator.onLine без результата запроса.

**TrashRestore/Purge:** обратимое удаление и окончательное уничтожение различаются подписью, расположением и подтверждением. Восстановление показывает объект/результат и возвращает к нему или обновлённому списку. Purge называет запись и связанные данные, имеет единственную финальную красную команду, начальный фокус «Отмена». Ошибка удаления файлов/записи не закрывает окно с ложным успехом. Disabled/readonly объясняют права и ограничения. Не использовать один диалог «Вы уверены?» без предмета для обоих действий.

<a id="pattern-session"></a>
### Роли, профиль, разрешения и сессия

**Role/Authority:** одинаковое действие одинаково называется для всех ролей, доступность следует доменным правам. Редкие запрещённые операции можно скрыть; ожидаемое пользователем действие — показать с причиной отсутствия права. При изменении прав во время редактора сохранить draft и объяснить невозможность отправки. Передача владельца/куратора содержит получателя, область, причину и подтверждение результата; не меняет роль во всей организации по похожей подписи. Аватар/должность — представление, не источник полномочий.

**Auth/Session:** видимые label email/password, корректные autocomplete и Enter-submit, pending/ошибка, без потери введённого email. «Запомнить email» не называется «Запомнить пароль». Потеря сессии отличается от пустых данных и отсутствия прав. После входа восстанавливается доступный маршрут/контекст, чужой draft не подтягивается. Logout показывает последствия для несохранённых/неотправленных изменений по фактической политике хранения, не обещает отправку без связи. Это UI-контракт; источники полномочий и серверные проверки остаются доменной реализацией, аудит backend здесь не выполнялся.

**PushPermission:** состояния supported/unsupported, prompt, granted, denied, подписан/не подписан на устройстве, pending и timeout видимы. Запрос browser permission только после понятного действия; denied не превращает кнопку в бесконечный повтор, указывается способ изменить настройку браузера. «Включить на этом устройстве» не означает включить для всей команды. Ошибка подписки имеет retry и не уничтожает inbox. Уведомления сами по себе не являются primary каждой страницы.

**Profile/Preferences:** имя/роль/подразделение, avatar с initials fallback, загрузка структуры и retry. Настройка темы имеет различие local preview / сохранено для аккаунта: выбор светлой/тёмной не должен отображаться как подтверждённая серверная запись до saveTheme. Переключатель представления, checkbox слоя карты и сохранение профиля не объединяются в одну ложную модель auto-save. Закрытие профиля возвращает фокус к avatar-trigger.

## 10. Источники конвенций и поддержка реестра

Дополнительно сверены [WAI Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/), [Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), [Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) и [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) — поведение, а не новая палитра. Дата сверки: 24.10.2026. Нативный control предпочтителен, когда закрывает задачу; роли не добавляются без соответствующего поведения.

Реестр [design-patterns.json](design-patterns.json) хранит проверяемые source-маркеры и отдельное наличие образца в каталоге. Команда `npm run qa:design-patterns` проверяет целостность ссылок/источников и новых явных type/role. Она не доказывает полноту пользовательских сценариев: при новом экране/режиме реестр дополняется вручную. Каталог и production-компоненты получают отметку готовности только после самостоятельного подтверждения поведения, обеих тем, responsive и прав роли.
