# Автоматический визуальный QA

Playwright запускает Chromium и снимает собранное приложение, а не отдельный макет компонентов. Это повторяемый цикл для UI: изменить код → запустить проверки → открыть снимки → исправить замечания → повторить проверку.

## Запуск

```sh
npm ci
npm run qa:visual:install
npm run qa:visual
npm run qa:visual:report
```

На новой Linux-машине с правами установки системных пакетов вместо `qa:visual:install` можно выполнить `npx playwright install --with-deps chromium --only-shell`. В текущем рабочем окружении Chromium Headless Shell установлен и проверен. Версия Playwright закреплена в package.json и lockfile; установка браузера должна выполняться этой же версией.

Для короткого цикла можно выбрать проект и экран:

```sh
npm run qa:visual -- --project=mobile-390-dark --grep="logist task"
```

Сервер автоматически пересобирает приложение и обслуживает его на `127.0.0.1:4173`; отдельно запускать Vite не требуется. Порт должен быть свободен.

## Матрица

Каждый размер проверяется в светлой и тёмной теме.

| Проект | Размер | Ввод |
| --- | --- | --- |
| mobile-360 | 360 × 800 | Touch |
| mobile-390 | 390 × 844 | Touch |
| tablet-768 | 768 × 1024 | Touch |
| desktop-1024 | 1024 × 768 | Mouse |
| desktop-1440 | 1440 × 900 | Mouse |

Диспетчер (`logist`): график сводки, статистика, три доски диспетчера, заявка, назначенное и активное задание, выезд, три раздела каталога и карта. Инженер: свой график, назначенное и активное задание, выезд. Администратор: тарифы, автопарк, пользователи и оформление. Это 21 ролевой экран × 10 сочетаний размера и темы = 210 сценариев.

Дополнительно проверяется фокус после клавиатурного Tab на всех 10 проектах. Четыре настольных проекта проверяют ширину рефлоу, эквивалентную 200%: исходный CSS viewport делится пополам, DPR равен 2, ввод мышью. Для 1024 × 768 это 512 × 384; для 1440 × 900 — 720 × 450. Это эмуляция доступной ширины, а не браузерный Ctrl+zoom или pinch zoom. Шесть ненастольных запусков этого теста намеренно пропускаются. Итого 224 выполняемых проверки и 6 пропусков.

Дополнительные снимки показывают раскрытые данные графика, результат и состав задания, окно выбора инженеров, карточку события расписания, присутствие и долю задания, экономику и историю выезда. Названия `task-result` относятся к снимку после подтверждения, что заголовок результата действительно находится во viewport и не закрыт липкой панелью.

Время фиксировано на 05.10.2026, язык браузера `ru-RU`, часовой пояс `Europe/Kyiv`, DPR 1, анимация сокращена. Перед снимком ожидаются данные и загрузка локальных шрифтов. Напоминание о сегодняшнем выезде закрывается обычной кнопкой «Позже»; оно не скрывается стилями.

## Результаты и проверка

- `test-results/visual-screenshots/<проект>/`: PNG и JSON с размерами контейнеров, темой и журналом чтения фикстур.
- `playwright-report/`: HTML-отчёт со снимками, включая дополнительные состояния.
- `test-results/visual/`: диагностические вложения и trace при ошибке.
- `test-results/visual-report.json`: машиночитаемый отчёт.

Тесты проверяют отсутствие горизонтального переполнения страницы и основной панели, необработанных ошибок JavaScript, обращения к удалённому Supabase и попыток записи. Эти проверки повторяются после дополнительных переходов и открытия вложенных состояний. Проверяется фокус и возврат к выбору инженеров после Escape, доступность результата у активного задания и скрытие управляющих полей выезда для инженера. Присутствие инженеру показывается записанными значениями и фактическим состоянием проверки; в этом блоке нет полей и кнопок изменения. Назначенное задание остаётся без ввода результата, активное — с доступным результатом. Горизонтальное прокручивание внутри расписания, канбана или таблицы допустимо. Проверяется открытие нужного ролевого экрана, нужная тема, загрузка содержимого и отсутствие экрана входа.

Автоматические проверки дополняются просмотром PNG: отступы, читаемость, скругления, цветовая иерархия, переносы текста и доступность действий. Успех тестов сам по себе не является заключением о качестве дизайна. Сейчас нет эталонов и попиксельного сравнения. Эталоны следует добавлять осознанно после согласования конкретного состояния.

## Изоляция и границы покрытия

`tests/visual/server.mjs` отдаёт production-сборку. Только в ответе локального стенда внешние подключения заменяются локальными Leaflet, Turf и шрифтами; Supabase SDK заменён синтетическим клиентом до загрузки приложения. Production HTML и механизм авторизации не изменяются. Все нелокальные запросы браузера блокируются. Фикстуры не содержат реальных сессий, паролей или пользовательских данных; операции записи отклоняются.

`tests/visual/mock-backend.mjs` — ограниченная модель чтения для перечисленных экранов, а не полноценный сервер. Она включает длинные названия, назначенное и активное задание, плановый и завершённый выезд, проверенное и непроверенное присутствие, историю, модели техники, материалы, структуру сотрудников и финансовую статистику. Операторы `not(is/eq/in)` фильтруют фикстуры, чтобы отсутствующие связи не создавали искусственные показатели. Карта использует настоящий локальный Leaflet с синтетическими точками; внешние тайлы и маршрутизатор не загружаются. При расширении экрана нужно расширять соответствующую фикстуру. Проверка не подтверждает реальную авторизацию, RLS, сохранение, офлайн-синхронизацию, drag-and-drop расписания или картографические тайлы. Для них нужны отдельные интеграционные сценарии. Firefox, Safari, экранная клавиатура и нативный browser zoom не входят в эту матрицу. Клавиатурные проверки ограничены фокусом диспетчера и открытием/закрытием выбора инженеров; они не подтверждают полную навигацию всего приложения.

## GitHub Actions

Workflow `visual-qa` запускается на PR в main, push в main и вручную. Он устанавливает Chromium, выполняет матрицу и сохраняет снимки, измерения, trace и HTML-отчёт артефактом на 7 дней, в том числе при неуспешном запуске. Секреты Supabase не нужны.

Снимки, отчёты и временные файлы игнорируются Git. В репозиторий входят конфигурация, тесты, фикстуры, workflow и инструкция; сгенерированные PNG не коммитятся.
