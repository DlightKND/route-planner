# Объединение GPS-треков перед привязкой · 08.10.2026

В GPS-журнале диспетчер/администратор отмечает треки одной машины. Порядок виден отдельным списком, изменяется стрелками или кнопкой «По времени». После «Посмотреть результат» показываются GPS-участки, их суммарный пробег и число точек. Кнопка объединения появляется после просмотра; для записи нужно основание. Созданный общий трек остаётся на разборе, затем используются прежние действия: создать цепочку, привязать к пустому выезду или отдельно подтвердить списание.

Порядок должен соответствовать исходному времени GPS без пересечений. Времена не переписываются, поездки разных машин и живой незавершённый трек объединить нельзя. Запись без свежего GPS более пяти минут закрывается по последней точке при подтверждённом объединении. За одну операцию выбирается от 2 до 20 треков. К уже объединённому треку можно добавить следующие участки.

`source_ranges` сохраняет исходные интервалы в заданном порядке. Исходники получают `merged` и ссылку `merged_into`, остаются в архиве и неизменяемой истории; сырые точки не удаляются и не перенумеровываются. Выбор блокируется и проверяется атомарно, с проверкой ревизий, числа точек и отсутствия чужой привязки. Общий расчёт и пагинация GPS используют только выбранные интервалы. Не выбранные между ними поездки не попадают в общий трек.

Пробег считается только внутри исходных участков; отрезки между ними не достраиваются. При привязке общего трека в `trip_tracks` сразу сохраняется разбор с отдельными измеренными сегментами и исходными границами. Это сохраняет правильное отображение после истечения хранения сырого GPS и исключает повторное построение маршрута через пропуски. Исходные даты и актуальная цена километра сохраняются в разрешении журнала.

Вся запись выполняется существующим способом: открытая SECURITY INVOKER RPC вызывает закрытую функцию с пустым search_path, проверкой `auth.uid()` и активной роли из profiles. У инженера нет доступа к объединению/сырым точкам; у anon нет EXECUTE; прямой UPDATE таблиц не выдаётся. Миграция не объединяет существующие поездки автоматически и не меняет бизнес-данные при установке.

Проверки: PGlite — выборочная область GPS, порядок/пересечения/дубли, разные машины, свежесть ревизии/числа точек, чужая привязка, повторное объединение, сохранение сегментов при импорте, одиночная привязка, роли, живая/устаревшая запись. Тестовая Supabase — реальная цепочка и импорт с проверкой выбранных точек и сохранённого разбора, полностью в rollback-транзакции. UI — выбор/перестановка/предпросмотр/отмена без записи на всех размерах в обеих темах.
