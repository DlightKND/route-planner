# Сохранение состава заявок, 09.10.2026

Исправлены случаи, когда создание или подтверждение ещё не сохранённой работы ошибочно сопровождалось сообщением об исторической корректировке, а первое заполнение выезда из задания требовало причину редактирования.

- Новая заявка сохраняется одним существующим RPC вместе с работами и запчастями. Запчасти можно заполнить до создания заявки.
- Незавершённая строка материала остаётся в полном локальном черновике. Пустое имя больше не удаляет строку из снимка, нулевое количество не подменяется единицей. Отправка ждёт исправления; интерфейс указывает поле и отличает черновик на устройстве от серверного сохранения.
- Подтверждение работ сначала проверяет и сохраняет новый состав. Отсутствие ID ещё не сохранённой работы больше не трактуется как историческая строка.
- Канонический офлайн-снимок заменяет редактируемый состав, сохраняя исторические строки и их происхождение. Последующее сохранение не отправляет их в обычный финансовый writer.
- При недоступном полном составе запчастей поля закрыты для изменения. Новые изменения не уходят обходным прямым запросом в историческую таблицу `job_parts`.
- После запуска задания поля запчастей закрыты вместе с кнопкой добавления. Прежде диспетчер мог менять поля, хотя автосохранение уже исключало материалы из запроса.
- Гарантийная работа получает объяснение из подсказки или значение «Гарантийный ремонт», которое можно уточнить. Поле помечено обязательным согласно существующим требованиям сервера.
- При создании выезда из задания первый план сохраняется с автоматическим аудиторским основанием. Последующие правки по-прежнему требуют причину. Признак первого заполнения связан с конкретным действием создания, а не с наличием ID или нулевой ревизией: связь с заданием сразу увеличивает ревизию нового выезда до 1.

Схема, серверные функции и права доступа не изменены. Старые офлайн-операции сохраняют прежний RPC. Исторические финансовые строки остаются защищены от обычного изменения и удаления.

## Проверка

- Unit и SQL-регрессии: 663 проверки в UTC и America/Los_Angeles; lint, production build и smoke.
- Браузер: создание заявки с работой и запчастью, пустой и нулевой материал с перезагрузкой, сохранение исправленного состава рядом с неизменённой историей, подтверждение новой работы, первый и повторный план выезда. Проверяются телефон, планшет и компьютер в обеих темах, а также существующие страницы заявки/задания/выезда для диспетчера и инженера.
- Реальные RPC в резервной базе под ролью `authenticated`, все данные откатаны: создание/редактирование работ и материалов; добавление к импортированному составу; неизменность полного JSON исторических строк; отказ при прямом изменении исторической строки; изменение плана задания без изменения его финансового снимка; первое заполнение выезда с фактической ревизией 1.

Проверки выполнялись на искусственных данных. Пользовательские заявки, задания, выезды и финансовые записи не редактировались.
