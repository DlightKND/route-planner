Перенесены структура шапки/периода, плоские desktop-вкладки, мобильная кнопка перехода, жёлтые кнопки фильтров/обзора, цвета и содержимое заданий/дороги, полоса факта, плавающий обзор и мобильные панели. Фильтры — черновик в аккордеонах: на ПК немодальная панель, на телефоне нативная модальная нижняя панель; применение не пишет данные расписания. Масштаб использует шкалу часов/дней/недель из HTML, сохраняет видимую дату, в недельном виде выбор участка увеличивает подробность без записи.

Статистика использует ту же структуру карточек, таблиц, диаграмм, KPI и источников, что макет. Действующие `plannerStatistics`/`dashboardMetrics` и финансовые снимки сохранены; неизвестный факт не превращается в ноль. Инженеру доступны его личные время/дорога, выезды и загрузка без финансов. Согласования, права и серверные операции нового графика не заменяются кодом демо.

Интеграционные поправки к геометрии: внешняя рамка/820px примера заменяются размерами рабочей области; отступ под исходную демонстрационную навигацию не дублирует настоящую; ширина колонок берётся из доступного календаря. Положение плавающих кнопок учитывает вставленные полосы факта и рабочего календаря, чтобы sticky-заголовки не блокировали их нажатие.

Проверка переноса — `tests/visual/planner-approved-fidelity.spec.mjs`: сравнивает реальные computed styles работающего приложения с неизменённым HTML, проверяет размеры/темы, draft/apply/reset фильтров, недельный масштаб, источники и таблицы. Отдельно сохраняются скриншоты обоих экранов. Исходные сценарии split/join/undo/fact продолжают использовать новый RPC. Скриншоты в git не добавляются.

В тестовой странице исходного HTML устранён только null-access `state.planFactSelected.person`, мешавший переключению роли на телефоне. Это временная защита загрузчика эталона; fixture, разметка и CSS не изменяются. Код демо в приложение не переносится.
