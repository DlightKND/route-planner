# Подтверждение присутствия: два состояния и сохранение без загрузки трека

## Поведение

- Выбор состояния — две обычные кнопки с `aria-pressed`: «Не подтверждена» / «Подтверждена». Одинаковый контрол на ПК и телефоне, без вкладок, нижнего индикатора и отдельного мобильного выпадающего списка.
- Каждая обнаруженная стоянка по умолчанию не подтверждена, даже если система подобрала заявку и команду. Её не требуется открывать, классифицировать или сохранять, чтобы подтвердить другие посещения.
- Явный выбор подтверждения открывает заявку, команду, время и распределение. Запись происходит отдельной кнопкой «Подтвердить присутствие» после прежних проверок. Сам выбор состояния ещё не записывает присутствие.
- Подтверждение можно снять, сохранив решение. В учёт не войдут часы и распределения этой остановки; GPS и история сохраняются. Старые решения «в пути»/«исключено» читаются без массового изменения данных, а в актуальном интерфейсе показываются как неподтверждённые.
- Счётчики показывают число подтверждённых стоянок, а не число разобранных записей. Неподтверждённая стоянка сама по себе не создаёт требование во «Внимание»; реальные проблемы трека и временные конфликты остаются там. Журнал по умолчанию показывает «Все», а фильтр без проблем называется «Без замечаний».
- В клиентском общем факте часов учитывается известная подтверждённая часть независимо от остальных обнаруженных стоянок. Когда нет ни одного достоверного решения, отсутствие факта не превращается в подтверждённый ноль. Некорректные исторические подтверждения продолжают блокировать признак известного итога. Незавершённость полной проверки и известность подтверждённой части — отдельные признаки.

## Сохранение

Повторный клик по уже выбранному фильтру журнала ничего не перезагружает. Ранее после `trip_presence_save_tasks` выполнялся полный повтор `mount`: заново читались весь `trip_tracks`, снимок поездки, заявки, распределения и создавались карты. Теперь обработчик получает версию записи из существующего RPC и перечитывает только сохранённую остановку и её распределения через существующие RLS.

Выбранная остановка, формы других стоянок, черновики, положение скролла и экземпляры карт сохраняются. Маркеры и временные конфликты обновляются локально. Кэш общих факт-часов после решения перечитывает только стоянки текущего выезда вместо всех выездов. История становится неактуальной и перечитывается при открытии, а не вместе с треком. После отдельной команды достройки трека полный повтор загрузки остаётся необходимым и сохранён.

Следующая запись использует только версию, возвращённую собственной серверной записью. Для завершённого выезда дополнительный пересчёт экономики выполняет условный UPDATE с версией из RPC присутствия и возвращает фактическую версию этого UPDATE; при конкурентном изменении пересчёт пропускается с предупреждением. Версия не угадывается и не продвигается фоновым чтением; конкурентные изменения по-прежнему отвергаются сервером. При успешной записи и ошибке последующего чтения интерфейс сообщает «Решение сохранено» и предлагает «Обновить решение» — повторяется только чтение, без дублирования записи. Повторный клик во время сохранения заблокирован. Права менеджера/куратора и режим чтения инженера сохранены.

## Проверка

Модульные сценарии проверяют отсутствие автоматического подтверждения, валидацию только явного посещения, повторную запись с актуальной версией, сохранение DOM/скролла и единственное чтение трека, восстановление после сбоя чтения и изоляцию черновиков. Браузерные сценарии обновлены для двух состояний, последовательного подтверждения/снятия, GPS-достройки, мобильных распределений и режима инженера.
