# DLIGHT · применение дизайн-системы 0.7

Основа: согласованное сравнение кита 0.6. Область внедрения — всё рабочее веб-приложение, все роли и динамически создаваемые элементы. Данные и правила прав доступа остаются в существующих обработчиках.

## Единый источник

`src/ui/component-tokens.css` хранит утверждённые числовые параметры desktop/touch и используется как приложением, так и парным китом. `src/ui/application-design-system.css` импортируется последним в `app.js`. Его приоритет перекрывает старые локальные правила внешнего вида. `installApplicationDesignSystem()` автоматически классифицирует существующие и добавляемые native-контроли, а не требует вручную включать стиль на каждом экране.

Цвета поступают из действующих THEMES; новые самостоятельные палитры не вводятся. Нейтральные выбранные сегменты отделены от жёлтых команд. Статусы и внутренние счётчики сохраняют смысловые цвета; известный ноль нейтрален. Внешняя цель фильтра со счётчиком — 36/48 px, счётчик — 24×22 px. Поля, кнопки и внутренний сегмент имеют общую геометрию из спецификации.

## Охват

| Область | Что получает общие правила | Проверка |
| --- | --- | --- |
| Вход, конфигурация, восстановление сеанса | Поля, основная команда, отмена, ошибки, focus | entry-elevation / windows |
| Сводка и личный график инженера | Вид, период, даты, команда, действия, карточки | application / design-states / engineer-dashboard |
| Диспетчер: заявки, задания, выезды | Вкладки, поиск, фильтры, статусы, counts, создание, меню | application / manager-workflow / production-design-system |
| Карточки заявки, задания, выезда | Вкладки, формы, история, комментарии, результат, приёмка, участники | application / entity-activity-flow / windows |
| GPS-журнал, маршрут, стоянки, распределение | Цели управления, выбор, даты, сводки, доказательства, редакторы | unified-journal / journal-reference / review-ergonomics |
| Карта, справочники, оборудование и материалы | Поиск, выбор, действия, FAB, открываемые карточки и редакторы | application / windows / production-design-system |
| Настройки: общие, парк, люди, оформление | Поля, radio/checkbox, сегменты, раскрытие и сохранение | application / windows |
| Уведомления, push, профиль | Фильтры, counts, редкие действия, окна, состояние записи | application / windows / production-design-system |
| Динамические popover/dialog | Те же геометрия, typography, радиусы и focus вне `.view` | application-design-audit в windows и общем smoke |

Нативные checkbox/radio имеют индикатор 20 px в строке-цели 48 px. Текстовый picker инженеров получил поиск и внутренний счётчик; исходный `select[multiple]` по-прежнему хранит значение. Slider имеет трек 4, бегунок 22, цель 48 px и точное числовое поле с ±. У кнопок сохранения общий индикатор busy сохраняет подпись, доступное имя и ширину.

Геометрия данных не является размером кнопки: положение и высота временного блока, линия маршрута, маркер и drag-handle определяются временем/координатами. Они используют общие тему и focus, а команды рядом используют общие цели 44/48 px. Подмена минутного блока кнопкой высотой 48 px исказила бы данные. Это правило соответствующего паттерна, не отдельное оформление раздела.

## Проверка и защита от повторного разнобоя

`tests/visual/application-design-audit.mjs` проверяет каждый видимый production-контрол: наличие классификации, реальную высоту, шрифт, тень, размер текста полей и inset radius. Он включён в общие сценарии приложения и окон. Отдельный `production-design-system.spec.mjs` проходит разделы под logist / engineer / admin, пять ширин и две темы и сохраняет снимки. Проверки не разрешают игнорировать целый раздел или контрол без класса UI.

Прежние проверки геометрии обновляются только при изменении утверждённого контракта: сегмент 8 → 6 px, touch 44 → 48 px, desktop M 44 → 40 px, фильтр ленты — pill вместо вкладки. Проверки hit-testing, сохранения/отмены, отсутствия переполнения и доступной рабочей области остаются обязательными.

Запуск: `npm run lint`, `npm run qa:design-patterns`, `npm test`, `npm run test:tz`, `npm run build`, `npm run qa:visual`. Конкретный результат, SHA и скриншоты фиксируются в PR и Actions. Отдельно необходимы проверки реальными пользователями и assistive technology; автоматический Chromium не объявляется VoiceOver/TalkBack-тестом.
