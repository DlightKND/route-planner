# DLIGHT · геометрия кита 0.5 / поведение 0.6

24 октября 2026. [Полное сравнение](https://dlightknd.github.io/route-planner/preview-design-system.html#full-kit). Это предложение для согласования, изолированное от production-приложения.

В 0.4 значительная часть оформления оставалась от 0.2; на desktop сенсорный переключатель был выключен. Дополнительно некоторые исправления были общими для обеих сторон. Поэтому «База / Предложение» показывали мало различий. Версия 0.5 содержит 66 отдельных пар: 58 семейств аудита и 8 основ. Старый адрес с #conventions при загрузке открывает новое полное сравнение. Ни одной рекомендации R01–R12 не оставлено без образца. Статический реестр проверяет соответствие текста рекомендаций, ID и правила; Chromium проверяет рендеринг всех пар.

В 0.6 основная геометрия сохранена; уточнён padding фильтра с мини-пилюлей, чтобы высота была ровно 36/48 px: дополнены сценарии фильтров, вкладок, профиля, навигации и комментариев. [Полнота поведения](design-kit-closure.md). Во время сохранения индикатор заменяет видимую подпись, сохраняя её доступное имя и габариты; редактирование и отмена временно блокируются.

## Как смотреть

1. Выберите паттерн слева или найдите его поиском. Фильтр R01–R12 показывает все примеры конкретного правила.
2. Сравните базу 0.4 и предложение 0.5 одновременно. Новые сценарии слева используют базовый язык компонентов; это не скриншот production и не доказательство существования старого бага.
3. Переключите Desktop / Touch. По умолчанию включён Touch, чтобы изменение 44 → 48 было видно сразу.
4. Выберите измеряемый элемент: основная кнопка, S/L, контейнер, внутренняя мини-пилюля, группа или стрелка.
5. Штриховка показывает CSS padding; контур — полный габарит. Под образцами — фактические bounding boxes и computed styles, включая все четыре padding, gap, радиусы, границу, шрифт/line-height/weight, тень и цвета. У switch отдельно выбираются цель нажатия, трек и бегунок; у выбора — строка и checkbox/radio. Жёлтая ячейка таблицы означает изменение; «Сохранено» означает намеренное отсутствие изменения.
6. Проверьте восемь состояний, тему и максимально доступную ширину образца. Контроли работают; записи, разрешения, сеть, сессии и серверные операции имитируются в памяти. Навигация сторонних сервисов и настоящая отправка файлов не выполняются.

## Точные параметры предложения

Почему padding кнопки M равен 9, а не 8: border-box 40 = line-height 20 + padding 9×2 + border 1×2. Для Touch: 48 = 24 + 11×2 + 1×2. Сетка размещения остаётся 4/8/12/16/24/32; геометрия внутреннего содержимого учитывает границу. В базовой версии min-height мог добавлять свободное пространство поверх CSS padding, поэтому одинаковый внешний размер не означает одинаковый computed padding.

У filter chip учитывается высота внутреннего счётчика 22 px: desktop 36 = 22 + 6×2 + 1×2, touch 48 = 22 + 12×2 + 1×2. Проверять одну лишь высоту строки текста здесь недостаточно.

Desktop M 40 согласован с `--control-h:40px` действующей `src/visual-system.css`. Icon target 44 оставлен больше текстовой кнопки из-за компактного символа; сенсорные цели — 48. Это собственная адаптация к вебу, не обещание нативного соответствия всем платформам.

## Рекомендации, которые видны в поведении

- R01/R02: размеры, padding, одинаковые соседние действия; busy, ошибка, повтор, отсутствие дубликата, сохранение ширины.
- R03/R04: мини-пилюля внутри фильтра, постоянный семантический цвет, одиночный выбор, равные сегменты, M3-вариант; статусы не нажимаются.
- R05/R06: немедленный switch с откатом, radio как черновик, native поля, валидация диапазона, отмена и focus return.
- R07/R08: поиск и checkbox-picker в popover/sheet, именованное удаление выбора; slider + число + ±; перестановка и время имеют точные альтернативы drag.
- R09/R10: корзина с Undo, alert без default, не исчезающее само сообщение, шторка с явным выходом, FAB над нижними контролами и скрытие без права.
- R11: тема, палитра, подписи/единицы, одинаковые таблица/диаграмма, focus и неинтерактивные статусы.
- R12: измерение/восстановление/принятие отдельно, распределение с остатком, dirty guard, конфликт версии, локальная очередь/сервер, восстановление демосессии, права и preview предпочтений.

Все 58 ID доступны в навигации кита. Для каждой рекомендации отображаются её текст, связанные R-коды, первичные гайдлайны и исходный файл. Отдельно показаны 8 основ: размеры, палитра, типографика, отступы, радиусы, тени, состояния, компоновка.

## Проверка

`npm run qa:design-patterns` проверяет соответствие рекомендаций визуальному реестру. `npx playwright test tests/visual/design-system-complete.spec.mjs --retries=0` проверяет все 66 пар в пяти ширинах и двух темах, реальные размеры, состояния и ключевые сценарии. Скриншоты каждой пары снимаются на desktop 1440/light и mobile 390/dark; основные геометрические примеры — на остальных конфигурациях. Результаты конкретного прогона — в GitHub Actions artifact `design-system-complete-*`.

Кит не заменяет production-пилот с реальными ролями, серверной валидацией, VoiceOver/TalkBack и экранной клавиатурой. Никакие сценарии не объявлены мигрированными только из-за появления красивого образца.
