## Поведение

- Инженер не создаёт задания: скрыты все входы, запрещён прямой вызов создания и серверная вставка, включая перенос остатка. Владение или кураторство не обходят запрет.
- По уточнению пользователя, более раннее начало дня расширяет окно и применяется сразу; более позднее требует руководителя. Конец дня остаётся на прежнем месте. Допуск можно увеличить сразу, уменьшение согласовывается. Для конца дня применяется то же правило расширения/сокращения.
- Инженер разделяет только собственный рабочий блок в выбранном дне. Предложение хранится отдельно, исходный план не меняется до решения. Прямой перенос, сброс или изменение `day_plan` инженером запрещены и при кураторстве.
- Первичный согласующий берётся из `employee_org.manager_id`. Без активного руководителя запрос явно отклоняется; случайного назначения другому администратору нет.
- Текущий согласующий может передать запрос своему руководителю; передача повторяется по цепочке. Предыдущий согласующий теряет право решения, сохраняется история. Циклы и неактивные аккаунты блокируются. Новый согласующий с ролью инженера получает только решение конкретного запроса, а не общие права диспетчера.
- Передача выше доступна в проверке выполнения задания, срока, переноса выезда, правок заявки, работ/материалов, присутствия, подтверждения выезда, распределения затрат и списаний/отмены списаний GPS-журнала. Общая очередь находится в меню диспетчера и на странице графика.
- Решения проверяют revision и снимок исходных данных. Старые RPC не позволяют обойти передачу. Согласующий видит предмет запроса и историю. Для разреза перед принятием загружается свежий график участвующих инженеров и проверяются пересечения.
- Мобильный ряд: поиск → квадратный жёлтый плюс 44×44 → меню 44×44. Полные подписи создания сохраняются на ПК и в `aria-label`. У инженера без права создания остаются поиск и меню. Для журнала сохраняется календарный период.
