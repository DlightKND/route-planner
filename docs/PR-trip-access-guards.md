# Защита настроек, трекинга и факта выезда

Продолжение после PR #52. Закрывает A01/A02 аудита перед публикацией новой карточки и изменением автоматического жизненного цикла.

## Почему

Через обновляемое представление settings_public можно было менять настройки в обход прав базовой таблицы. ors_proxy затем получал bearer-токен пользователя. Семь служебных RPC пропускали NULL вместо роли неактивного/отсутствующего профиля. Дополнительно обнаружены nullable-проверки состава команды в trip_start/trip_finish и удаление GPS до проверки, что выезд находится в корзине.

## Изменения

- settings_public остаётся доступным для чтения authenticated. Запись отозвана на уровне представления и отдельных столбцов. Чтение инженерами не зависит от расширения доступа к исходной таблице settings.
- Браузер отправляет ORS-запросы только в /functions/v1/ors подключённого проекта; запрещены чужой origin, credentials в URL, query/hash и перенаправления. Текущий production-адрес совместим.
- Проверки ролей в семи служебных RPC закрыты при NULL. is_owner_or_mgr требует активный профиль; trip_start/trip_finish проверяют активность и явно отклоняют неизвестный состав. Строка выезда блокируется до проверки текущего статуса.
- Окончательное удаление сначала блокирует и проверяет выезд в корзине; вызов для действующего выезда оставляет его GPS на месте.
- Новых публичных API нет; вызовы исправленных функций запрещены PUBLIC/anon и доступны authenticated с внутренними проверками.

## Проверки

Полный набор: 290/290 тестов в основном часовом поясе и America/Los_Angeles; lint, build и smoke проходят. Локальный Supabase/Docker не запущен: SQL проверялся в PGlite, а не в полном стенде Supabase.

42 SQL-теста выполняют миграцию на минимальном контракте схемы в PGlite: anon, отсутствующий профиль, inactive, engineer, logist, admin; отказ в записи настроек, сохранение чтения, разрешённые действия менеджеров/второго инженера, защита трека. 13 тестов проверяют адрес назначения токена и параметры реального сетевого вызова. Полная схема production на тестовом стенде остаётся отдельной проверкой перед применением миграции.

Исходные определения затронутых функций зафиксированы в tests/fixtures/trip-access-before.sql только для воспроизведения регрессий. Там намеренно находятся старые небезопасные проверки; этот файл не применяется к Supabase.

## Развёртывание

Миграция создана CLI, проверена локально; production не изменён. Применить миграции на стенде с полными политиками/триггерами, проверить реальные роли, затем подготовить production и отдельно запустить публикацию main. Откат UI не требует возврата небезопасных прав.

## Следующий этап автоматизации

Текущий vehicle_depot_track уже буферизует точки до автоматического старта, но выбирает один ближайший выезд при неоднозначности. Завершение остаётся кандидатом; trips_autoclose_stale ставит время now() по возрасту плана. trip_tracking_cancel/reassign меняют привязку ранее накопленного трека. Следующее изменение должно заменить эти переходы единым журналом событий: неоднозначность — на проверку, потеря связи — пробел, устойчивое возвращение — фактическое время прибытия, кнопки — сигналы с сохранением исходных наблюдений. Этот PR меняет только авторизацию этих операций, а не их бизнес-семантику.

Основание модели прав: [Supabase — RLS и права представлений](https://supabase.com/docs/guides/database/postgres/row-level-security).
